# Day 2: Organizing Active Directory, Help Desk Tasks and Lockout Policy
Date: 2026-11-16

## Task
Build out the homelab.local domain with organizational units, groups and test users, practice common help desk tasks, set an account lockout policy, and start a Windows 11 client VM to join the domain.

## Challenges
- My first group-creation commands failed because the long commands were split across two lines. Each PowerShell command has to be typed as a single line.
- The Windows 11 client VM (CLIENT01) stayed on a black screen after I started it. Clicking the window, waiting, and resetting the VM did not fix it.

## How I solved it
- Retyped each group command as one line, then confirmed the groups existed.
- For the client VM, I stopped and will try a different approach next session.

Organizational units and groups:
```powershell
$d = "DC=homelab,DC=local"
New-ADOrganizationalUnit -Name "Staff" -Path $d
New-ADOrganizationalUnit -Name "IT" -Path $d
New-ADGroup -Name "Allstaff" -GroupScope Global -Path "OU=Staff,$d"
New-ADGroup -Name "HelpDesk" -GroupScope Global -Path "OU=IT,$d"
```
I created two OUs, one for staff and one for IT, and two security groups, one for all staff and one for the help desk. I checked with `Get-ADOrganizationalUnit` and `Get-ADGroup` that all four existed with no errors.

Test users and group membership:
```powershell
$o = "OU=Staff,$d"
$pw = Read-Host "Test password" -AsSecureString
foreach ($n in "alopez","bcarter","cdiaz","dreyes","ekim") { New-ADUser -Name $n -SamAccountName $n -Path $o -AccountPassword $pw -Enabled $true }
Add-ADGroupMember -Identity Allstaff -Members alopez,bcarter,cdiaz,dreyes,ekim
Add-ADGroupMember -Identity HelpDesk -Members ekim
```
I created five test users (A. Lopez, B. Carter, C. Diaz, D. Reyes and E. Kim) with a password prompt that hides what I type. I added all five to the all-staff group and only E. Kim to the help desk group. I verified with `Get-ADUser -SearchBase` and `Get-ADGroupMember`.

Help desk tasks in Active Directory Users and Computers:
- Reset A. Lopez's password and ticked "User must change password at next logon".
- Disabled B. Carter's account, then re-enabled it.

Account lockout policy:
- In Group Policy Management, I edited the Default Domain Policy.
- Under Computer Configuration, Account Lockout Policy, I set the account lockout threshold to 3 invalid attempts and accepted the suggested 30-minute duration.
- I ran `gpupdate /force` to apply the policy, and both the computer and user policy updates completed successfully.

Client VM attempt:
- Downloaded the official Windows 11 evaluation ISO.
- Created CLIENT01 in VirtualBox with the appropriate RAM, CPUs and disk, attached to the same NAT network as the domain controller.
- The VM showed only a black screen, even after waiting and resetting it. I will try a different solution next session.

## Skills and lessons
- Creating OUs, groups and users with PowerShell (`New-ADOrganizationalUnit`, `New-ADGroup`, `New-ADUser`, `Add-ADGroupMember`)
- Verifying changes with `Get-` commands
- Resetting passwords and disabling and re-enabling accounts in Active Directory Users and Computers
- Setting an account lockout policy with Group Policy and applying it with `gpupdate`
- PowerShell commands must be typed as one line
- When a VM won't start, stop and troubleshoot instead of repeating the same steps
